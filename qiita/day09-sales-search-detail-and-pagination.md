# 【Day 09】売上検索APIを作る：期間指定・詳細取得・ページング

シリーズ：**Next.js・Python・AWSで作る売上管理システム**

公開予定：2026年12月9日（日本時間）。開発・レビューとQiita公開は別に管理しています。

## はじめに

[Day 8](https://github.com/hirolisberger/sales-manager-dashboard/blob/day08/qiita/day08-sales-registration-and-amount-calculation.md)で登録した売上を、HTTPで検索・参照できるようにします。今回は`GET /sales`と`GET /sales/{sale_id}`を追加しました。

期間・商品・状態で絞った一覧と、全明細を含む詳細を用意します。複数日に分かれたデータを1件ずつ取得しても、重複や取りこぼしが起きないことを確認します。画面・訂正・取消・認証は後続Dayです。

## この記事の到達点と前提

- 過去の売上を開始日・終了日・商品・状態で検索できる
- 売上全体の合計と、商品で絞った明細の金額を区別する
- 署名付きカーソルで日付をまたいで次のページへ進める
- 売上の詳細と、その版を示すETagを取得する

確認日は2026年11月8日。macOS ARM64、Python 3.14.9、uv 0.13.6、MiniStack 1.5.33とDay 8までの固定依存を使用しました。依存やロックファイルは更新していません。

## 1. 期間と並び順を決める

一覧の検索条件を次のようにしました。

| 条件 | ルール |
| --- | --- |
| start_date / end_date | 必須。両端を含む1〜366日 |
| product_id | 任意。対象商品の明細を持つ売上 |
| status | all（既定）/ confirmed / cancelled |
| limit | 1〜100、既定50 |
| cursor | 直前の応答のnext_cursor |

逆順の期間・不正日・未知や重複した条件は422です。367日以上も拒否します。検索には未来を含められます。「今月末までを見る」操作を許可しても、未来の売上を登録できることにはなりません。売上登録のJST本日以前というルールはDay 8のままです。

並び順は計上日の降順、同じ日付なら売上UUIDの降順です。過去日の売上を後から登録できるため、登録日時順とは区別します。

## 2. 日付別データを順に読む

Day 8で売上本体と一緒に保存した`DAY#{計上日}`のデータを使います。終了日から開始日へ向かい、各パーティションをQueryします。

```text
終了日の日付別データ → 前日 → … → 開始日の日付別データ
各日付の中では、売上UUIDの降順
```

`ScanIndexForward=False`で逆順に読みます。既存のリポジトリが指定する`ConsistentRead=True`を使い、非同期のGSIに依存しない構成を維持しました。Queryのソート順と、テーブルへの強い整合性の読み取りは公式資料で確認できます。[AWS Query資料](https://docs.aws.amazon.com/amazondynamodb/latest/APIReference/API_Query.html)

取得した売上からstatusを確認し、商品指定があれば該当明細を選びます。商品が現在無効でも、過去の取引を検索できます。

## 3. 商品で絞った金額を分けて返す

コーヒー550円×2と紅茶330円×1の売上を、紅茶で検索した場合を考えます。

| 一覧の項目 | 値 |
| --- | --- |
| total_amount_yen | 売上全体の1,430円 |
| matched_amount_yen | 紅茶分の330円 |
| matched_quantity | 紅茶の1個 |

売上全体の1,430円を紅茶の売上として使わないように、別の項目にしました。同じ商品が複数明細にある場合は、対象となるすべての明細を合算します。商品条件がなければ全明細が対象です。

一覧には明細配列を含めません。詳細のGETは保存済みの全明細と商品スナップショット、合計を返します。商品マスタを改名・値上げ・無効化しても、過去の明細は変わりません。

詳細は`SALE#{売上UUID}/CURRENT`をGetItemで読み、ETagとして版番号も返します。存在しない売上や他店舗のIDは404 SALE_NOT_FOUNDです。

## 4. 内部のページと、APIのページを分ける

DynamoDBのQueryは、Limitまたは1MiBの区切りでページを分けます。内部のLimitは評価対象の件数なので、APIが返したい件数とは一致しません。Itemsが空でもLastEvaluatedKeyがあれば続きがあります。[AWS Query資料](https://docs.aws.amazon.com/amazondynamodb/latest/APIReference/API_Query.html)

今回は、APIが返せる残り件数を内部QueryのLimitに指定しました。商品や状態が一致しないデータは読み進め、日付の末尾なら前日へ移動します。返せる件数を超えて一致売上を先読みし、その位置を飛ばして次のページへ進むことは避けます。

カーソルには「次に読む日付」と「その日の最後に消費したキー」を保存します。日付を切り替えた直後ならキーはnullです。APIが返すnext_cursorがnullになったら終端です。未読データが条件に合うかは未確定なので、最後に空のitemsを返す場合もあります。

## 5. カーソルを検索条件へ結び付ける

Day 7のHMAC署名処理を共通化し、商品と売上で継続位置の検証を分けました。商品の形式・期限は維持し、売上用には日付と日付別キーの関係も検証します。

売上カーソルは店舗・資源・期間・商品・状態・並び順・limitに結び付けます。途中で条件を変更した場合や、改ざん・15分の期限切れ・API再起動後は400 INVALID_CURSORです。署名の比較には`hmac.compare_digest`を使います。[Python HMAC資料](https://docs.python.org/3.14/library/hmac.html)

HMACは暗号化や本人認証ではありません。また、強い整合性のQueryでも、複数のページを一つのデータ時点には固定できません。今回の「重複・欠落なし」は同時更新がない場合の検証です。ページの間に登録・日付訂正が行われる場合のスナップショット保証はありません。

## 6. ローカルで詳細・ページングを確認する

すべて`sales-manager-dashboard/`で実行します。[DAY9_COMMANDS.md](https://github.com/hirolisberger/sales-manager-dashboard/blob/day09/docs/DAY9_COMMANDS.md)の手順1〜4でMiniStack・テーブル・APIを準備し、確認用商品2件と売上4件を登録してください。日付は日本時間の実行日から計算します。

| 売上 | 計上日 | 明細と金額 |
| --- | --- | --- |
| 1 | 2日前 | コーヒー550円×2、紅茶330円×1＝1,430円 |
| 2 | 前日 | 紅茶330円×2＝660円 |
| 3 | 当日 | コーヒー550円×1＝550円 |
| 4 | 当日 | 紅茶330円×1＝330円 |

詳細は次のコマンドで確認できます。

```sh
day09_sale_id=$(python3 -c 'import json; print(json.load(open(".cache/day09-sale1.json"))["id"])')
curl -i "http://127.0.0.1:8000/sales/$day09_sale_id"
```

200・ETag: "v1"・2明細・合計1,430円が目印です。紅茶で絞った一覧と比べても、詳細は全明細を返します。

一覧は、準備済みの条件ファイルからURLを作って取得します。

```sh
day09_query=$(python3 -c 'import json, urllib.parse; print(urllib.parse.urlencode(json.load(open(".cache/day09-query.json"))))')
curl -fsS "http://127.0.0.1:8000/sales?$day09_query" \
  -o .cache/day09-page.json
python3 -m json.tool .cache/day09-page.json
```

対象は今回登録した紅茶ID・3日間・1件ずつです。既存のデータがあっても同じ商品IDだけを検索できます。最初は当日の330円が返ります。

続きの取得は手順書の「次のページへ進む」コマンドを繰り返してください。毎回、直前の応答からnext_cursorを取り出すため、仮の文字列を置換する必要はありません。330円、660円、売上全体1,430円・紅茶分330円の順に確認できました。条件を変更したい場合はカーソルを付けずに最初から検索します。

生成したGETのURLはブラウザーでも開いてJSONを読めます。売上管理画面は後続Dayで作成します。
