# Qiita Advent Calendar 2026：本編25記事とDay 0準備編

## シリーズの方針

**シリーズ名：Next.js・Python・AWSで作る売上管理システム**

Day 3でMiniStackとLocalStackを比較し、MiniStackを採用する構成とした。以後の計画と記事はその実装に合わせる。Day 0〜2の承認済み原稿は、企画時点のLocalStackを含むシリーズ表記を保持する。

売上管理システムを題材に、要件定義からローカル開発、API、画面、業務ロジック、テスト、AWSへのデプロイと運用までを25回で記録する。

Day 1までの準備記録は [DAY0_SETUP.md](DAY0_SETUP.md)、公開用のDay 0本文は [準備編の記事](../qiita/day00-project-setup-and-github.md) にまとめる。Day 0はQiita公開を想定した追加記事とし、本編25記事とは別枠で公開日未定として管理する。Day 1〜25の番号と公開予定日は維持する。

対象読者は、JavaScript / TypeScriptやPythonの基礎を知っていて、フロントエンドとバックエンドをつないだアプリケーション開発やAWSの利用を学びたい人を想定する。

- 各記事のタイトルには `【Day NN】` を付け、本文冒頭にシリーズ名と前後の記事へのリンクを記載する。
- 1記事につき一つの主題を設け、そのDayの成果物と確認結果までを扱う。必要な前提や前日までの実装も示す。
- タイトル・概要は企画案。本文は各Dayの実装と一緒に作成し、実際の採用技術・検証結果に合わせて調整する。
- PythonのAPIフレームワーク、データベース、認証、IaCなどの候補技術は、採用・検証を経てから記事内で確定事項として扱う。
- Dayは記事と作業の単位であり、開発は毎日行う必要はない。1回の作業は原則一つのDayを対象とする。
- 公開予定日は2026年12月1日〜25日、日本時間で1日1記事に固定する。開発・レビューの実施日とは分けて管理し、予定日前に全体公開しない。
- 記事本文は下書きから作成する。Qiitaへの投稿・更新・限定共有・予約登録・全体公開は、ユーザーの明示的な許可がある場合のみ行う。レビュー承認だけでは投稿しない。
