## 3. 架空の売上で計算を確認する

本日を **2027-01-05（JST）に固定した架空の検証ケース** とする。現在の日時でアプリへ未来日登録したという意味ではない。

取引時の単価は、コーヒー `P001` が550円、紅茶 `P002` が330円。後から商品マスタのコーヒーを600円に変えても、既存明細の550円は変えない。

| 売上ID | 計上日 | 明細 | 訂正・取消前の合計 |
| --- | --- | --- | --- |
| S001 | 2026-12-01 | コーヒー550円×2、紅茶330円×1 | 1,430円 |
| S002 | 2026-12-01 | 紅茶330円×2 | 660円 |
| S003 | 2026-12-02 | コーヒー550円×1 | 550円 |
| S004 | 2026-11-30 | コーヒー550円×1 | 550円 |
| S005 | 2027-01-01 | 紅茶330円×1 | 330円 |

S001をコーヒー1・紅茶1へ訂正し、S002を理由付きで取り消す。S001は版2・880円、S002は版2・`cancelled` とし、取消前の金額660円は保存したまま集計対象から外す。

| ケース | 期待値 | 対応ルール |
| --- | --- | --- |
| SC-01：変更前の2026年12月 | 1,430 + 660 + 550 = 2,640円 | BR-01・BR-04 |
| SC-02：S001の訂正後 | 880 + 660 + 550 = 2,090円。訂正前の1,430円を加えない | BR-03 |
| SC-03：S002の取消後 | 880 + 550 = 1,430円。11月・翌年1月分は含めない | BR-03・BR-04 |
| SC-04：取消後の日別 | 12月1日880円、12月2日550円、残りの日は0円 | BR-04 |
| SC-05：取消後の商品別 | コーヒー2個・1,100円、紅茶1個・330円。総額1,430円 | BR-01・BR-04 |
| SC-06：紅茶だけを指定 | S001の紅茶330円のみ。売上全体の880円を使わない | BR-04・BR-05 |
| SC-07：商品マスタを600円へ変更 | 既存の12月分は1,430円のまま | BR-01・BR-03 |
| SC-08：過去月を指定 | 2026年11月550円、2027年1月330円。月別で合算しても期間外は除外 | BR-02・BR-04 |
| SC-09：12月のCSV明細 | S001の2明細とS003の1明細、計3行・1,430円。取消分と履歴版は出力しない | BR-05 |
| SC-10：計上日を変更 | S003を12月2日から11月30日へ訂正すると、12月880円・11月1,100円へ移る | BR-02・BR-03 |

SC-10はSC-03の結果から別分岐として計算する。SC-09のCSVはSC-03時点の条件であり、SC-10の後の期待値と混同しない。

## 4. 境界と異常系の確認項目

| ケース | 設計上の期待 |

| BC-01：単価550.5円、数量1.5 | 丸めず入力エラー。税込整数円・整数数量の合意と一致 |

| BC-05：売上の計上日に存在しない日付・未来日を指定 | 入力エラー。未来日の判定はAPIの時計とJSTで行う案。検索期間には月末など未来の日付を含めてよい |

| BC-08：取消済みを訂正・復活する | 拒否。必要なら新しい売上として登録 |
| BC-09：無効商品を含む過去の売上 | 表示・訂正・取消は可能。無効商品を新しい売上へ追加しない |
| BC-10：登録直後の集計をGSIだけで読む | 結果整合性による遅延を見落とさない。Day 4で要件を満たす読み取り方式を検証 |
